# 릴리스 평가 규약

이 규약과 합격선은 `korean-prose-editor`의 평가 출력을 만들기 전에 고정한다. 후보 결과를 본 뒤 기준을 완화하거나 사례를 교체하지 않는다. 실패와 `uncertain`도 원시 결과에 그대로 남긴다.

## 역할과 입력 격리

각 실행은 서로 다른 Codex 서브에이전트가 selection, editing, verification을 순서대로 맡는다. 세 역할은 서로 다른 canonical lowercase UUID를 사용한다.

- selection은 원문, 요청, 문체 조건만 본다. 스킬 본문, 후보, 기대 판정은 보지 않는다.
- editing은 원문, selection 결과, 보호 문자열과 editing policy만 본다. 기대 점수와 검증 결과는 보지 않는다.
- verification은 원문, 후보와 이 규약만 본다. 편집 이유, 작업 과정, 자체 평가는 보지 않는다.
- finalization은 결정적 스크립트로 한 번만 실행한다. `fail` 또는 `uncertain` 구간을 원문으로 되돌리고 전역 보호 조건이 깨지면 전체 원문을 반환한다.

같은 입력 세트를 독립적인 역할 체인으로 세 번 실행한다. 불일치와 `uncertain` 사례만 구현에 참여하지 않은 별도 감사자가 재판정한다.

## 판정 축

사례별로 의미 보존, 원문 격식과 관점, 전문 용어와 고정 명칭, 보호 문자열, 자연스러움, 수정 필요성 판정을 기록한다. 부정, 조건, 양태, 날짜·시각·수치·단위, 직접 인용, URL, 이메일, 코드, 명령과 경로의 연결 관계를 포함한다. 다른 표현도 가능하다는 이유만으로 자연스러운 원문을 바꾸면 과잉 편집이다.

## 고정 세트

- 기존 100건은 알려진 회귀 세트로만 사용한다.
- 새 holdout 30건은 구현을 보지 않은 작성자가 만들었으며 `edit`, `retain`, `defer`를 각각 10건 포함한다.
- 실행자에게는 기대 판정을 제거한 입력만 제공한다. 정답과 집계 키는 최종 집계 단계까지 분리한다.

## 릴리스 합격선

세 실행이 각각 아래 조건을 모두 만족해야 한다.

- 보호 문자열 정확 보존: 100%
- 기존 100건 의미 보존: 99% 이상
- 기존 100건 개선율: 80% 이상
- 기존 100건 회귀율: 5% 이하
- 기존 100건 과잉 편집 억제: 90% 이상
- 새 holdout의 중대한 의미 변화와 보호 문자열 손상: 0건
- 새 holdout 개선율: 80% 이상
- 새 holdout 억제 성공률: 85% 이상
- 역할 재사용, 증거 누락, 평가 기준 변경: 0건

한 조건이라도 미달하면 해당 실행과 릴리스 판정은 실패다. 환경 또는 도구 오류는 기능 통과로 올리지 않고 `inconclusive`로 기록한다.
